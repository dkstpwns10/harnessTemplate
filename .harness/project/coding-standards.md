# Coding Standards (프로젝트 소유 — 리뷰어가 읽는다)

`reviewer`가 Standards 축에서 적용하는 규칙. 구현 중에는 읽지 않아도 된다 (구현자의 context를 아끼고, 규칙 적용은 리뷰 단계가 맡는다).

넣는 것: **판단이 필요한 규칙**만 — 파일 간 일관성, "주변 스타일과 맞는가", 모듈 경계, 이름 규칙의 의도처럼 검사기가 대신할 수 없는 것.
넣지 않는 것: 기계적으로 판정되는 규칙(금지 API, import 형태, 포맷, 파일 위치). 그런 규칙은 lint·정적 분석에 추가하고 `verify.conf`의 `FULL_CMD`에 연결한다.

규칙마다 한 줄 이유를 붙인다. 이유를 모르는 규칙은 지울 수도 지킬 수도 없다.

## 규칙
- <예: 도메인 계층은 Spring 타입을 import하지 않는다 — 도메인 테스트를 컨테이너 없이 돌리기 위해>
