# 병렬 worktree 자동화

**왜 넣지 않는가**: 여러 작성자가 동시에 코드를 바꾸면 통합·충돌 해결·검증 범위가 복잡해진다. 1인 개발 흐름에서 이 비용이 이득보다 크고, CLI가 이미 worktree·백그라운드 세션을 제공한다.

**대신**: 한 번에 작업 하나(`current.md`), 큰 기능은 티켓 frontier를 순서대로. 병렬로 돌릴 때의 최소 규칙만 지킨다 — 한 worktree에 쓰는 에이전트는 하나, 읽기 전용 에이전트는 공유 가능, lockfile·공용 manifest는 통합 담당만 수정.

**다시 검토할 조건**: 서로 독립인 티켓이 frontier에 여럿 쌓이고 대기 시간이 실제 병목이 될 때.
