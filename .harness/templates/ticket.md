# Ticket

큰 기능을 세션 하나에 들어가는 조각으로 나눌 때 쓴다 ([feature](../workflows/feature.md)의 "티켓 분할"). 위치: `docs/tickets/<prd-slug>/NN-<slug>.md`. `NN`은 의존 순서(막는 티켓이 앞)로 01부터 매긴다. 티켓 하나에 파일 하나.

```
# NN. <제목 — 이 티켓이 되게 하는 동작>
- Status: OPEN | IN PROGRESS | DONE
- Blocked by: 01, 02 | 없음
- PRD: docs/prd/<slug>.md (AC1, AC3)

## Delivers
(끝까지 동작하는 것 한두 문장. 이 티켓만으로 시연·검증할 수 있어야 한다)

## Scope
(건드릴 것으로 예상하는 파일·디렉터리 — backtick 경로)

## Verify
(완료를 확인할 방법: 테스트 seam, verify 범위)

## Notes
(작업 중 알게 된, 다음 티켓에 필요한 사실. 끝나면 codemap/decisions 후보)
```

## 나누는 규칙
- **수직 슬라이스**: 각 티켓은 필요한 모든 층(스키마, 로직, API, UI, 테스트)을 얇게 관통한다. "모델만", "테스트만" 같은 층별 티켓은 만들지 않는다.
- **세션 하나 크기**: 새 세션이 PRD와 이 티켓만 읽고 끝낼 수 있어야 한다.
- **준비 리팩터링 먼저**: 구현을 쉽게 만드는 구조 변경이 있으면 첫 티켓으로 둔다 ("변경을 쉽게 만든 다음, 쉬운 변경을 한다").
- **막는 관계는 진짜 의존만**: 앞 티켓의 결과가 없으면 시작할 수 없을 때만 `Blocked by`에 적는다.
- **넓은 기계적 변경은 예외** (컬럼 이름 변경, 공용 타입 변경처럼 한 번에 수많은 호출부가 깨지는 것): expand → migrate → contract 순서로 나눈다. 새 형태를 옆에 추가(expand) → 호출부를 패키지·디렉터리 단위로 옮기는 티켓들(migrate, 각각 expand에 막힘) → 옛 형태 삭제(contract, 모든 migrate에 막힘). 각 티켓이 끝날 때 빌드가 깨지지 않는다.
- 진행 순서: **frontier**(막는 티켓이 모두 DONE인 OPEN 티켓) 중 하나를 고른다.
