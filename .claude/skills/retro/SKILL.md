목적은 **다음 세션이 같은 실수를 덜 하게 환경을 바꾸는 것**이다. 코드 자체의 리뷰가 아니다. 하네스 파일은 고치지 않고 제안만 한다 (AGENTS.md 규칙 9, 10).

## 1. 근거 모으기
- 대상 세션: 사용자가 지정한 것, 없으면 현재 세션. 지난 세션 기록 위치 — Claude Code: `~/.claude/projects/<프로젝트 경로의 / 를 - 로 바꾼 이름>/*.jsonl`, Codex: `~/.codex/sessions/<YYYY>/<MM>/<DD>/*.jsonl`. 전부 읽지 말고 사용자 메시지, 도구 호출, 실패한 명령, hook 차단 메시지만 추린다.
- 함께 읽는다: `docs/improvements.md`(이미 기록된 것과 몇 번째인지), `.harness/out-of-scope/`(이미 거절된 개념과 다시 검토할 조건), `.harness/state/last-verify.log`, `git log`(해당 기간).
- 인용할 때 비밀 값은 `<REDACTED>`로 바꾼다.

## 2. 후보 찾기 (분류마다 "언제 보는가"에 해당할 때만)

| 분류 | 언제 보는가 | 제안의 모양 |
|---|---|---|
| **반복 교정** | 사용자가 같은 지적을 두 번 이상 함 | 아래 다른 분류 중 어디로 막을지 정해 제안 |
| **자동 검사** | 검사기가 잡을 수 있는 실수를 AI가 함, 또는 저장소에 lint·타입검사가 `FULL_CMD`에 연결돼 있지 않음 | 기계적 위반(금지 API, import 형태, 파일 위치, 포맷)은 **규칙 문장 대신 검사**: lint 규칙, `verify.conf`, guard hook. 이미 있는데 연결이 안 된 검사가 있는지 먼저 확인 |
| **리뷰 규칙** | 리뷰가 놓친 문제가 나중에 드러남 | 판단이 필요한 것만 `.harness/project/coding-standards.md`에 한 줄 + 이유 |
| **탐색** | 파일·진입점을 찾는 데 오래 걸림 | `codemap.md` 항목 (경로 근거 포함) |
| **지침 정리** | AGENTS.md·skill에 있지만 행동을 바꾸지 못한 문장, 매번 우회되는 단계 | 삭제, 또는 검사로 대체. 우회가 잦은 단계는 너무 무거운 것이다 |
| **도구 비용** | 같은 큰 출력을 반복해 읽음, 느린 명령을 반복 실행 | 범위를 좁힌 명령, verify scope, 스크립트 |
| **정보 접근** | 결정적 정보(서버 로그, 외부 상태)를 볼 수 없어 막힘 | 로그 tee, 읽기 전용 접근 방법 — 사용자 결정 사항으로 |

## 3. 보고
- 심각도 순으로 후보를 나열한다. 각 후보: **관찰**(세션·명령·인용 — 근거 없는 후보는 쓰지 않는다) · **분류** · **제안**(어느 파일을 어떻게) · **비용**(유지 부담, 작은 작업에 추가되는 대기).
- 규칙을 **늘리는** 제안과 **줄이는** 제안을 같은 무게로 다룬다. 실제로 관찰된 실패가 없는 "있으면 좋을" 개선은 후보에서 뺀다.
- 사용자가 고른 후보만 `docs/improvements.md`에 한 줄씩 기록한다 (Status `APPROVED` 또는 `OPEN`). 프로젝트 소유 파일(`codemap`, `coding-standards`, `project.md`)은 승인 후 고치고, 하네스 파일은 `HARNESS_UNLOCK` 절차로 사용자가 결정한다.
